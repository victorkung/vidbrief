*Andrej Karpathy: Software Is Changing (Again) · Y Combinator · Published Jun 19, 2025 · 40 min*

## High-Level Overview
Andrej Karpathy argues software is entering a third era where natural language replaces code as the primary interface. This shift requires treating large language models as new operating systems with distinct hardware and memory constraints. Developers must build legible, auditable infrastructure now to safely manage autonomous agents in the coming decade.

## Context
Former Tesla AI director Andrej Karpathy draws on his experience at Stanford, OpenAI, and Tesla to frame this transition. His insights matter because the industry is currently in a volatile 1960s-style computing phase that demands immediate architectural adaptation.

### Chapter 1: Three Eras of Software Evolution
Andrej Karpathy defines three distinct software eras, arguing LLMs now act as programmable computers that consume and replace traditional code stacks.

- [00:01:02] **Three Software Eras**: Karpathy maps evolution from code-based Software 1.0 to data-tuned Software 2.0 and prompt-driven Software 3.0.
- [00:03:03] **English as Code**: Software 3.0 lets users program computers in natural language, treating LLMs as new programmable hardware.
- [00:04:03] **Neural Network Migration**: Tesla's experience shows neural networks eating through traditional C++ stacks to handle complex reasoning tasks.

### Chapter 2: LLMs as New Operating Systems
Karpathy frames LLMs as a new OS with a consumer-first adoption curve, requiring partial autonomy tools to manage their flawed, memory-limited nature.

- [00:09:09] **OS Analogy**: LLMs act as OSes with models as CPUs and context as memory, mirroring utility and fab economics.
- [00:10:11] **System Architecture**: The model serves as the CPU while the context window functions as the system's memory.
- [00:11:13] **1960s Parallel**: Current LLM computing resembles the 1960s, relying on expensive centralized cloud time-sharing rather than personal devices.
- [00:18:22] **Partial Autonomy**: Build apps with an "autonomy slider" letting users tune AI intervention from simple completion to full agent execution.

### Chapter 3: Human AI Collaboration Loops
Karpathy argues we must keep AI "on the leash" via small code chunks and auditable artifacts to ensure safety while building legible infrastructure for future agents.

- [00:23:25] **Keep AI Leashed**: Break tasks into small chunks and spend time on concrete prompts to verify code before running the loop.
- [00:25:29] **Create Auditable Artifacts**: Build intermediate constraints like syllabi to prevent agents from getting lost and ensure safety.
- [00:35:37] **Build for Agents**: Replace click instructions with executable `curl` commands to make digital infrastructure legible to LLMs.
- [00:37:39] **Autonomy Timeline**: View models as current utilities; expect the autonomy slider to shift right as infrastructure matures over the next decade.

## Key Takeaways
- **Software 3.0 Paradigm**: Treat LLMs as programmable computers where natural language replaces traditional code stacks for execution.
- **New OS Architecture**: Design systems where the LLM acts as the CPU and the context window functions as volatile memory.
- **Partial Autonomy Control**: Implement an "autonomy slider" allowing users to tune AI intervention levels from simple completion to full agent execution.
- **Legible Infrastructure**: Replace click-based workflows with executable `curl` commands to ensure agents can reliably navigate digital environments.
